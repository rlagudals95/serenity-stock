# Serenity 가설과 시안 v1

## 합의된 방향

- 목표: 유용한 종목 발견 이후 재방문·지속 사용.
- 시각 기준: 사용자가 지정한 WWIT의 2021-02-16 뱅크샐러드 홈·추천 화면. 밝은 표면, 그린 포인트, 굵은 핵심 문장, 정돈된 목록, 충분한 여백.
- 대상 가설: 투자 기회를 찾지만 공개 의견을 모두 읽을 시간이 부족한 개인 투자자. 투자 기간·숙련도는 아직 검증하지 않았다.
- 이번 산출물: 검증 가설과 인터랙티브 화면 시안. 종목명·내용·시점은 모두 시안용 가상 예시이며 실제 투자 추천이나 성과 데이터가 아니다. 서비스 코드·운영 데이터는 변경하지 않는다.

| H4 | 비교가 필요한 사용자는 A 브리핑형, 선택 부담이 큰 사용자는 B 집중형에서 더 쉽게 첫 판단에 도달한다 | 동일한 세 종목으로 A/B 순서를 교차해 과제 수행하고, 실제 되돌아가기·후보 전환·저장/보류 관찰 | 과제 완료율, 판단까지 시간, 후보 간 비교 성공률 | 어느 한 안이 이해도 하락 없이 더 빠른지 확인. 차이 없으면 비교와 재방문을 함께 지원하는 A 유지 | 선호 설문만으로 승자를 정하지 않음. 소수 관찰을 통계적 유의성으로 해석하지 않음 |

성공 기준은 관측 결과가 아닌 사전 가설이다. 5명 사용성 테스트는 문제 발견용이며 시장 전체 효과의 증명이 아니다. 주식 수익 개선과 UI의 사용성 개선은 별도로 검증해야 한다.

## 시안 A — 오늘의 브리핑 (우선 추천)

### 첫 방문

한 줄 가치 제안 → 후보 최대 3개 → 각 후보의 새 근거/핵심 위험 → 판단 근거 보기.
사용자가 여러 후보를 비교하기 쉽도록 정렬된 목록으로 구성한다. 과거 상승 사례와 설명용 집계 지표는 첫 화면에서 제외한다.

### 재방문

중요한 변화 2건 → 저장 당시의 이유와 새 근거 → 변화 검토 → 확인 완료.
관심 종목의 변화가 새 후보보다 먼저 나온다. 모든 변경을 확인하면 ‘새로 확인할 변화 없음’ 상태로 바뀐다. 확인 여부는 투자 판단의 변경과 구분한다.

### 상세

최근 변화 → 기대 근거 / 반대 근거 → 다음 확인 항목 → 예시 근거 펼치기 → 관심/보류.
저장 뒤 짧은 이유를 선택 입력할 수 있으며, 관심 종목 화면에서 내용을 다시 확인한다. 시안의 저장은 시안 안에서만 유지하며 실제 서비스 저장 완료로 표현하지 않는다.

## 시안 B — 한 종목씩 집중

한 후보의 기대·위험을 읽고 근거를 검토하거나 다음 후보로 이동한다. 후보 번호와 이동 버튼을 제공해 순서를 잃지 않도록 한다. 강제 스와이프·시간 제한·매수 유도는 사용하지 않는다.

장점 가설: 한 번에 읽을 양이 적고 첫 행동이 분명하다.
약점 가설: 종목 간 비교와 이전 후보 재탐색에 시간이 더 걸릴 수 있다.
후보 데이터와 순위는 A와 동일하게 유지한다.

## 시안 인터랙션 범위

- A 첫 방문 / A 재방문 / B 집중 탐색을 비교할 수 있다.
- 오늘, 관심 종목, 전체 탐색 메뉴가 작동한다.
- 종목 상세, 기대·위험·예시 근거, 관심/보류 저장, 저장 취소, 관심 이유 기록을 사용할 수 있다.
- 재방문 시안에서는 이전/새 근거 비교와 확인 완료를 통해 남은 변경 수가 줄어든다.
- 전체 탐색에서 가상 종목을 검색할 수 있다.
- 디자인 조정에서 모서리와 간격을 비교할 수 있다.

| 상태 | 처리 원칙 |

| 조건을 충족한 후보 없음 | 임의 종목으로 3개를 채우지 않고 검색과 관심 종목으로 안내 |
| 관심 종목 없음 | 후보 살펴보기로 연결 |

| 데이터 갱신 지연 | 마지막 정상 시점 표시, 현재/오늘이라는 표현 중단 |

## 계측과 다음 결정

시안에서는 실제 분석 이벤트를 전송하지 않는다. 운영 실험 전 `candidate_impression/open`, `evidence_open`, `risk_open`, `review_saved`, `watchlist_saved`, `change_impression/open`, `change_reviewed`를 구현한다. 사용자·세션·종목·실험 버전·변경 ID·데이터 기준 시점을 함께 기록한다. 메모 원문은 계측에 포함하지 않는다.

최상위 지표 후보는 다른 날 저장 종목의 새 근거나 결과를 확인한 주간 고유 사용자 수다. H3의 실험 비교에는 사용자 유입 규모에 덜 영향받는 코호트 재방문율을 사용한다. 변경이 있던 사용자와 없던 사용자를 분리한다.

다음 결정은 시각적 선호와 함께 ‘A에서 후보 비교가 쉬운가 / B에서 판단 시작이 쉬운가 / 재방문 시 변화가 충분히 중요한가’를 보고 내린다. 결과가 나오기 전에는 A를 구현 출발점으로 권하되 H3를 검증된 효과로 취급하지 않는다.

## 시안 점검 결과

브라우저에서 상세 진입 → 관심 추가 → 이유 기록 → 관심 목록 확인, 재방문 변화 2건 → 1건 → 모두 확인 상태, B안 후보 전환, 전체 탐색 검색을 확인했다. 새로고침 후 시안의 기록 복원도 확인했다. 약 320px 콘텐츠 폭에서 목록·집중 화면의 가로 넘침을 점검했으며 확인한 브라우저 오류 로그는 없었다. 이는 시안 동작 검증이며 실제 리텐션 실험 결과가 아니다.

## A안 선택 이후 구현 상태

사용자의 A안 선택에 따라 서비스 화면에 브리핑 구조를 반영했다. 앞 절의 ‘서비스 코드를 변경하지 않음’은 초기 시안 산출 시점의 범위이며, 이번 구현에는 적용하지 않는다.

홈은 기존 순위를 유지한 후보 최대 3개와 기대·위험을 보여준다. 재방문에서는 관심 종목의 마지막 확인 의견을 기준으로 새 주장·새 위험·관점 변경을 먼저 보여주며, 상세에서 변경된 분석가의 이전/새 의견을 모두 비교하고 확인 완료할 수 있다. 저장 이유와 보류 상태는 관심 목록에 다시 나타난다. 근거 부족·후보 없음·관심 목록 없음·새 변화 없음·갱신 지연·저장 실패를 별도 처리했다.

현재는 브라우저 단위의 지속 사용 흐름이다. 기존 관심 쿠키를 유지하고 메모 및 분석가 최신 의견 스냅샷은 localStorage에 보관한다. 모든 중간 게시글의 변경 이력, 기기 간 동기화, 알림 전송은 포함하지 않는다. 홈의 ‘변화’는 수집된 공개 의견의 변화이며 실시간 가격 변화가 아니다. 후보 조건을 충족하는 종목이 1개이면 1개만 보여준다.

기본 행동 이벤트는 메모 없이 브라우저 로컬 큐에만 쌓인다. H3 실험을 운영하려면 중앙 분석 연동, 안정적인 사용자·세션/변경 ID, 노출 이벤트, 기준 시점, 실험군 배정을 추가해야 한다. 이번 구현·테스트 통과는 리텐션 가설의 검증 결과가 아니다.

## 추천 후보 1개 문제에 대한 수정

누적 긍정 우세 필터는 방향성 의견 최소 3개를 요구했다. 샘플에서 ASTS·RKLB는 근거가 있는 긍정 의견이 2개여도 `insufficient`로 분류되어 COHR 1개만 노출됐다. 이를 홈 추천 자격과 동일하게 취급한 것은 다양한 사용자 관점의 발견 경험과 맞지 않았다.

홈은 원문 URL과 구체적인 긍정 주장이 있으며 긍정 소스 수가 부정 소스 수보다 많은 종목을 후보로 삼는다. 중복 종목 없이 ‘여러 의견 비교’(긍정 소스 수), ‘새 변화 포착’(첫 언급/새 주장 시점), ‘사업 성장 추적’(반복 매출·채택 확대·시장 확대 표현)의 세 관점으로 선정한다. 성장 후보를 먼저 확보한 뒤 새 변화 후보를 선택해 관점 간 중복을 피한다. 특정 관점이 없으면 ‘추가 관점 비교’로 정직하게 대체하고, 원문 없는 종목으로 수량을 채우지 않는다. 성장 표현 매칭은 초기 규칙이며 투자 기간·위험 등급·기업 가치 판단을 의미하지 않는다.

각 추천에는 선정 이유, 기대 근거, 핵심 위험, 다음 확인 항목을 노출한다. 펼친 영역에서 작성자별 주장·작성일·원문 및 과거 완료 표본 유무를 확인한다. 샘플 결과는 COHR / ASTS / RKLB이며 티커를 고정한 추천이 아니다. 기존 전체 탐색의 누적 관점 집계와 필터는 유지한다. 현재 입력만으로 배당·저평가·저위험 추천은 제공하지 않으며 실제 개인화에는 사용자 선호와 추가 재무 데이터가 필요하다.

## 발견 화면의 후킹과 정보량 재설계

문제: ‘여러 의견 비교 / 새 변화 포착 / 사업 성장 추적’은 서비스가 하는 일을 설명하지만 투자자가 얻을 기회를 상상하게 하지 못했다. 선정 이유·주장·위험·확인 조건·출처를 모두 홈에 반복해 세 종목을 비교하기 전에 긴 글을 읽게 했다.

변경: 홈은 사업의 기회 한 가지를 제목으로 제시한다. 예를 들어 공급 병목 → ‘AI가 커질수록, 더 필요한 기업’, 상용화 → ‘상용화 문턱, 다음은 매출일까?’, 반복 매출 → ‘한 번의 흥행보다, 반복해서 버는 사업’. 공개 주장에 해당 주제가 있을 때만 편집 문구를 사용하며, 일치하지 않으면 중립적인 제목과 원래 주장의 짧은 발췌를 쓴다. 종목명으로 이야기를 고정하거나 시총·수익률·저평가 여부를 추측하지 않는다.

홈에는 주제·두 줄 제목·설명 한 줄·기업·위험과 하나의 진입 링크만 둔다. 상세에서 기회가 되는 이유 / 놓치면 안 될 위험 / 다음 체크포인트와 원문을 읽는다. 새 변화가 없으면 관심 목록 안내를 추천 아래로 내리고, 실제 새 변화가 있으면 위에 유지한다. 데스크톱은 세 기회를 나란히, 모바일은 세로로 보여준다.

사용자가 제안한 ‘작지만 주목받는 기업’은 좋은 기회 분류다. 실제 노출 조건에는 기준일이 있는 시가총액, 관심 증가 비교 기간 및 집계, 위험 근거가 필요하다. 시총이 작다는 이유만으로 상승 여력이나 고수익을 확정하지 않는다. 해당 데이터가 없는 현재 화면에는 가짜 소형주 분류를 만들지 않았다.

검증할 것은 카드 클릭률과 상세의 근거 열람·저장·후속 확인이다. 클릭만 늘고 위험 이해나 저장 후 재방문이 떨어지면 후킹의 성공으로 보지 않는다.

## 메인 기대 중심 구성

최신 사용자 요청으로 홈 추천 카드의 위험 요약을 상세로 모았다. 홈은 기회 주제 → 후킹 제목 → 짧은 성장 관점 → 기업 → ‘성장 이야기 보기’로 구성한다. 상세의 위험 근거와 원문은 그대로 제공한다. 이 변경은 정보 노출 단계의 변경이며 추천 데이터나 수익 가능성의 보증을 추가하는 변경이 아니다. 카드 클릭 이후 근거 열람·저장·재방문까지 함께 확인한다.

## 인플루언서 의견을 핵심 콘텐츠로 승격

문제: 서비스의 차별점인 작성자별 의견이 고급 분석 안에 접혀 있고, 메인에는 누가 이 기회에 주목하는지 보이지 않았다.

변경: 메인의 기회 카드에 원문·긍정 주장이 있는 작성자의 이름(최대 2명+나머지 인원)과 긍정 인원수를 표시한다. 상세는 ‘의견 한눈에’를 기본 탭으로 삼고, 최근 입장 집계와 인물별 핵심 주장·작성일·원문을 첫 영역에 놓는다. 부정 의견도 펼치지 않고 읽을 수 있다. 한 사람이 여러 글을 써도 최근 입장 한 건만 집계하며 수익 확률이나 매수 추천으로 표현하지 않는다.

긴 분석은 작성자·원문 URL·주장이 모두 일치하는 게시글에 한해서 연결한다. 일치하는 분석이 없으면 다른 게시글의 근거를 대신 붙이지 않고 확인된 원문 링크만 보여준다. 기회·위험·체크포인트는 별도 펼침 요약으로 유지한다. 기존 하단 분석가 비교는 중복 제거하고 과거 통계·언급 추이로 한정한다.

가설: 메인의 출처가 드러나면 근거가 궁금한 클릭이 늘고, 상세에서 여러 인물의 의견을 비교한 사용자의 관심 저장과 후속 확인이 증가한다. 근거 펼치기·원문 클릭은 기존 브라우저 로컬 evidence_open 이벤트로 기록하며, 리텐션 효과 확인은 중앙 분석 연동 후에 가능하다.
