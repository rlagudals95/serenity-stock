# 종목 발견과 재방문을 위한 UX 개편 제안

작성일: 2026-09-26. 제안 단계이며 제품 코드는 변경하지 않았다.

## 사용자 지정 UI 톤앤매너

기획과 별도로 [WWIT의 뱅크샐러드 화면 기록(2021-02-16)](https://wwit.design/2021/02/16/banksalad/)을 시각 레퍼런스로 적용한다. 홈과 추천 화면 원본을 확인했다. 밝은 바탕과 그린 포인트, 굵은 핵심 숫자, 읽기 쉬운 한글, 옅은 회색 구획, 여유 있는 목록 간격을 참고한다. 모바일 화면의 구조 자체를 복제하지 않고 현재 웹 서비스에 맞게 적용한다. 세부 기준은 프로젝트 루트 `.impeccable.md`에 반영했다. 기존 기획과 성공지표는 이 레퍼런스로 변경하지 않는다.

## 목표와 근거

사용자가 선택한 우선 목표는 **유용한 종목 발견 후 재방문·지속 사용**이다.
가설 타깃은 공개 투자 의견을 참고하지만 모든 자료를 읽을 시간이 부족한 개인 투자자다. 투자 기간·숙련도는 아직 확인하지 않았으므로 특정 매매 성향으로 개인화하지 않는다.

제품의 약속: **검토할 투자 기회를 좁혀주고, 관심을 가진 이유가 달라지면 다시 확인하게 한다.**

현재 소스와 로컬 fixture 화면의 홈·종목 상세를 확인했다. 운영 데이터, 실제 사용자 행동, 모바일 사용성은 이번 검토 범위 밖이다. 따라서 아래는 검증할 제품 가설이며 확정적인 전환율 예측이 아니다.

관찰:
- 홈에는 이미 최대 3개 후보가 있다. 하지만 후보, 성과 사례, 4개 탐색 탭, 6개 정보 열을 가진 테이블이 이어져 탐색 목적이 분산된다.
- 상세 상단은 종합 신호, 시장 반응, 여러 관점 라벨, 8개 집계 지표, 분석가별 의견 순이다. 주요 위험과 다음 확인 항목은 뒤에 배치된다.
- 관심 종목은 목록 필터로 접근한다. 저장 이후의 변화와 마지막 확인 시점을 중심으로 한 전용 흐름은 없다.
- `ResearchTab`의 저장은 컴포넌트 상태와 시각만 바꾼다. 실제 기록 저장이 없어 재방문 가치와 저장 지표를 훼손할 수 있다.
- 검토한 src/package.json에서 제품 행동 분석 도구 연동을 발견하지 못했다. 기준 수치는 계측 후 확보해야 한다.

## 정보 구조

주 메뉴는 **오늘 확인할 것 / 내 관심 종목 / 전체 탐색**으로 구성한다.

| 영역 | 핵심 질문 | 기본 정보와 행동 |
| --- | --- | --- |
| 첫 방문 홈 | 무엇부터 살펴볼까? | 기준을 충족한 후보 최대 3개. 지금 확인할 이유, 핵심 위험, 근거 시점. 주 행동은 판단 근거 보기 |
| 재방문 홈 | 내가 보던 것에서 무엇이 달라졌나? | 마지막 확인 이후 관심 종목의 새 근거·관점 변경·위험 변화. 신규 후보는 다음 순서 |
| 종목 상세 | 계속 검토할 가치가 있나? | 최근 변화 → 기대 근거 → 반대 근거 → 다음 확인 항목 → 관심 등록 또는 보류 |
| 내 관심 종목 | 어떤 종목을 다시 봐야 하나? | 저장 이유, 이후 변화, 마지막 확인 시점, 사용자가 정한 다음 확인 항목 |
| 전체 탐색 | 직접 비교하고 싶은 종목은? | 기존 검색, 표, 정렬, 세부 필터를 보존 |

변화가 없으면 '마지막 확인 이후 새로운 근거가 없습니다'와 데이터 기준 시점을 표시한다. 매 방문마다 새 종목을 억지로 채우거나 반복 의견을 새 기회로 포장하지 않는다. 후보가 1개면 1개만 보여준다.

초기에는 전체 시장의 기회가 아닌 **추적 중인 공개 소스에서 발견한 후보**임을 짧게 밝힌다. 과거 적중률이나 언급량을 개인의 예상 수익률로 표현하지 않는다.

## 상세 화면 예시

다음은 실제 종목 추천이 아닌 콘텐츠 구조 예시다.

> 종목 A — 이번에 확인할 이유
>
> 변화: 신규 고객 인증에 대한 새 근거가 추가됐습니다.
>
> 기대 근거: 고객 확대가 향후 매출 성장으로 이어질 수 있다는 의견입니다.
>
> 반대 근거: 인증 이후 실제 주문 전환은 아직 확인되지 않았습니다.
>
> 다음 확인: 실적 발표에서 신규 고객 매출 기여를 확인합니다.
>
> [관심 종목에 추가]  [나중에 검토]  [근거 원문]

기본 요약에서도 위험과 데이터 최신성은 유지한다. 원문, 전체 의견, 분석가 비교, 계산 방법, 표본과 성과 상세는 펼쳐서 읽게 한다. 실적 일정 등 새로운 외부 데이터가 필요한 정보는 연결 전까지 임의로 채우지 않는다.

관심 등록 직후 이유를 선택하거나 한 줄 기록할 수 있게 하되 강제 입력으로 막지 않는다. 외부 알림은 사용자가 구독한 경우에만 제공하며 초기 버전은 앱 안의 변경 목록으로 검증한다.

## 성공지표와 계측

최상위 제품 지표 후보: **최근 7일 동안, 이전 세션에서 검토·저장한 종목을 다른 날 다시 열고 새로운 근거 또는 결과를 확인한 고유 사용자 수**.
이는 투자 수익의 대리지표가 아니라 지속적인 리서치 가치의 대리지표다. 실제 수익 개선은 별도 데이터와 검증이 필요하다.

| 단계 | 정의 | 판단 목적 |
| --- | --- | --- |
| 첫 가치 도달률 | 첫 방문 후 24시간 안에 근거·위험을 펼쳐보고 관심 또는 보류로 저장한 신규 사용자 / 24시간 관찰이 끝난 신규 사용자 | 후보가 검토할 가치를 제공하는가 |
| D7 유효 재방문율 | 최초 검토 저장 후 7~13일에 저장 종목의 새 근거·결과를 확인한 사용자 / 해당 기간 관찰이 끝난 최초 검토 저장 사용자 | 저장이 지속 사용으로 이어지는가 |
| 변경 검토율 | 변경을 노출받고 근거를 확인한 사용자 / 해당 변경을 노출받은 사용자 | 재방문 화면의 변화가 유용한가 |
| 보조 지표 | 후보 상세 진입률, 첫 가치 도달까지 걸린 시간, 표본 설문상 판단 도움 정도 | 병목 위치와 체감 가치 |
| 품질 지표 | 저장 실패율, 오래된 데이터 노출률, 저장 취소, 외부 알림 도입 시 해제율 | 숫자를 올리면서 경험을 해치지 않는가 |

노출·펼치기·저장 행동은 내용을 이해했다는 직접 증거가 아니다. 사용자 인터뷰/간단 설문으로 보완한다. 변경이 실제 존재한 사용자와 없었던 사용자의 재방문율을 나누어 본다. 방문 횟수와 체류시간 증대 자체를 성공으로 보지 않는다.

이벤트 제안: `candidate_impression`, `candidate_open`, `evidence_open`, `risk_open`, `review_saved`, `watchlist_saved`, `change_impression`, `change_open`, `outcome_open`.
공통 속성은 익명 사용자 식별자, 세션, 종목, 화면 위치, 실험 버전, 데이터 기준 시각. 변경에는 고유 change_id를 둬 중복을 제거한다. 저장 이벤트는 실제 보관 성공 후에 기록한다. 메모 본문은 분석 이벤트에 보내지 않는다.

## 실행 순서와 검증

1. **기반:** 리서치 실제 저장, 관심 종목 저장 시각·이유·마지막 확인 시각, 이벤트 계측을 먼저 준비한다. 현재 관심 종목 쿠키만으로는 기기 간 기록과 사용자별 변경 확인을 충족하지 못하므로 저장 범위와 사용자 식별 방식을 결정한다.
2. **첫 가치:** 홈의 후보 영역을 유지하면서 중복 섹션을 전체 탐색/성과 상세로 옮긴다. 상세 첫 화면을 이유·위험·다음 확인 중심으로 바꾼다. 후보 순위 계산은 유지해 화면 효과를 구분한다.
3. **재방문:** 관심 종목의 새 근거와 이전 근거를 비교할 수 있게 한다. 공개 게시글의 반복·단순 재인용은 중요한 변화로 집계하지 않는다. 변경 정의와 저장 스냅샷이 필요하다.
4. **검증 후 확장:** 앱 안의 변화 검토가 유용한지 확인한 뒤 사용자 선택 알림, 투자 기간별 개인화, 결과 복기로 확장한다.

우선 사용자 5명 정도에게 '검토할 종목 하나를 고르고 이유·위험을 설명한 뒤 저장하고, 다음 방문에 변화 찾기' 과제를 준다. 이는 사용성 문제를 찾는 탐색이며 정량적 효과 증명이 아니다.

계측 기반을 먼저 수집하고 트래픽이 충분하면 사용자 단위로 기존/개편 화면을 배정한다. 첫 실험은 후보와 순위 기준을 동일하게 두고 정보 위계의 영향을 본다. 최소 효과 크기와 필요 표본은 기준 수치를 얻은 뒤 정하며, D7 관찰 기간이 끝난 코호트만 비교한다. 트래픽이 작으면 인터뷰와 코호트 추적을 사용하고 인과적 개선을 단정하지 않는다.

## 디자인 점검 참고

기존의 차분한 색상, 원문 추적, 세부 필터 접기, 후보 수 제한은 유지할 장점이다. 수정 우선순위는 화면 위계·저장 신뢰성·재방문 흐름이다. 정형 AI 디자인 패턴 검사(`impeccable --json`)는 `src/features/tickers`, `src/components`에서 0건을 보고했다. 이는 좋은 UX나 접근성 준수를 입증하지 않으며 별도 CSS와 실제 이용 흐름의 한계를 반영하지 못한다.

독립 소스 검토의 우선 이슈는 실제 저장 누락(P1), 홈의 경쟁하는 탐색 흐름(P1), 상세의 집계 우선 위계(P1), 상승 사례와 현재 기회의 혼동 가능성(P1), 저장 이후 변화 확인 동선 부족(P2)이다. 초보 방문자는 지표를 해석해야 하고, 바쁜 재방문자는 지난번 이후 변화를 다시 찾아야 하며, 기록하는 사용자는 저장 완료를 믿고 기록을 잃을 수 있다.

휴리스틱 점수는 소스 기반 잠정 진단이며 사용자 조사 결과가 아니다.

| 휴리스틱 | 점수 /4 | 주요 근거 |
| --- | --- | --- |
| 시스템 상태 표시 | 2 | 실제 보관 없는 저장 완료 표시 |
| 현실 언어 일치 | 2 | Catalyst·고유 스레드 등 해석 부담 |

| 오류 예방 | 2 | 과거 성과와 현재 기회 혼동 가능성 |

인지 부하 체크는 단일 초점·정보 묶음·우선순위·결정 순서·점진적 공개의 5개 항목에서 개선 필요로 판정했다. 정형 패턴 검사 결과와 함께 보면 외형보다 과업 구조가 우선이다.

후속 디자인 작업을 스킬로 실행한다면 `/distill`로 첫 화면 정보를 압축하고, `/layout`으로 첫 방문과 재방문의 순서를 나누고, `/clarify`로 판단 중심 문구를 작성한 뒤 `/polish`로 마무리한다. 저장·계측·변경 추적 구현은 이 디자인 작업과 별도로 필요하다.
